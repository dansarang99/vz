# [참조 02] 토큰 제로 & 제로토발(Zero-Token, Zero-Heat) 운영 프로토콜

> **우리팀 절대 비장의 무기**: **모달 연동 제로토발 (Zero-Token, Zero-Heat)**  
> **최고 의사결정권자 하명**: 본부장님 (Chief Executive Officer)  
> **핵심 원칙**: **지갑(토큰) 절약보다 노트북 발열 0% 유지(Zero-Heat)가 최우선 목표이다.**

---

## 1. 왜 토큰 제로 & 제로발열(제로토발)인가?

대규모 프로젝트(예: 100페이지 기획서, 영상 시나리오, 딥러닝 추론, FFmpeg 영상 인코딩)를 진행할 때, 대부분의 사람들은 하나의 대화창에 모든 것을 쏟아붓거나, 무모하게 로컬 노트북에서 수 시간씩 풀로드 연산을 돌립니다.  
그 결과:

```
[치명적 2대 파산 시나리오]
1. 토큰 파산: 에러 로그와 터미널 출력이 대화창을 오염시켜 50,000 토큰 초과 ➔ AI 치매(Amnesia) 발생
2. 하드웨어 파산: 로컬 온보드 GPU/CPU가 2시간 이상 과열되어 화면 줄무늬 및 메인보드 냉납 손상 발생
```

**모달 연동 제로토발 프로토콜**은 메인 채팅창의 토큰 소모를 **0%에 수렴**시키는 동시에, 모든 고부하 연산을 **클라우드(Modal)로 100% 오프로딩하여 노트북 발열을 0%로 완벽 사수**합니다.

---

## 2. 제로토발 5대 핵심 메커니즘

### 1) 격리된 워크스페이스 (Context Isolation)
- 메인 대화창(본부장 ↔ 총괄팀장)에는 프로젝트의 **명령과 최종 결과 요약**만 남깁니다.
- 실제 데이터 전처리, 파이썬 스크립트 실행 등은 메인 채팅창 밖에서 격리하여 실행합니다.

### 2) ⚡ [비장의 무기] 모달(Modal) 클라우드 오프로딩 (Zero-Heat Architecture)
- 비디오 인코딩(`ffmpeg`), 음성 전사(`whisper`), 음성 합성(`TTS`), AI 이미지 생성(`Stable Diffusion/Flux`) 등 10초 이상의 연속 고부하 연산은 **로컬 실행을 영구 금지**합니다.
- 서버리스 GPU/CPU 플랫폼인 **Modal(modal.com)**의 원격 컨테이너에서 무소음으로 실행하고, 로컬로는 완성본만 다운로드합니다.
- **결과:** 노트북 CPU 점유율 1~3%, 발열 0%(상온 유지), 팬 소음 0dB!

### 3) 파일 기반 핸드오프 (File-Based Handoff)
- AI끼리 대화로 수만 자의 텍스트를 주고받지 않습니다.
- 에이전트 간 데이터 전달은 파일(`blueprint.json`, `result/[001]_script.md`)로 수행하여 토큰 소모를 0으로 유지합니다.

### 4) 0-Error 자가 치유 루프 (Self-Healing Loop)
- 에러가 나면 메인 창에 묻지 않고, 대장장이와 프로그래머가 자체적으로 수정·재실행하여 100% 무결점 상태로 총괄팀장에게 인계합니다.

### 5) 시리얼 번호 영구 보존 (`[001]` ~ `[999]`)
- 모든 산출물은 `[001]`, `[002]` 고유 번호를 부여하여 `result/`에 꼬리물기로 영구 보존합니다.

## 3. 토큰 소비량 및 하드웨어 안전성 비교 분석

| 구분 | 일반적인 로컬 직접 실행 방식 | 우리팀 모달 연동 제로토발 체계 |
| :--- | :--- | :--- |
| **메인 창 토큰 소비** | 회차당 20,000 ~ 100,000+ 토큰 | 회차당 **500 ~ 1,500 토큰 미만 (Token-Zero)** |
| **노트북 발열 & 하드웨어** | **심각한 고열 (화면/메인보드 손상 위험)** | **발열 0% (상온 유지, 하드웨어 수명 100% 보호)** |
| **연산 처리 속도** | 로컬 Iris Xe 내장그래픽 (느림, 멈춤) | **클라우드 4코어 CPU / T4 GPU (초고속)** |
| **실행 비용** | 기기 수리비 50만~80만 원 리스크 | **작업 1회당 0원 ~ 8원 (매월 $30 무료 크레딧 내)** |
| **컨텍스트 오염율** | 매우 높음 (지시사항 망각 발생) | **0% (항상 첫 프롬프트처럼 맑음)** |
| **산출물 관리** | 채팅창 복붙 필요 (누락 위험) | **로컬 `result/`에 자동 파일 영구 보존** |
