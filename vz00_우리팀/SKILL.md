                                ▲▼ (전담 브리핑 / 하명 접수)

   - **가변 TF 편성 대권:** 미션에 따라 전문 부대원을 자유롭게 소집·교체·해산 (참조 11 문서)

========================================================================================
                                ▲▼ (토큰 제로 고속 통신 / 파일 기반 핸드오프)
========================================================================================
🏭 [Tier 3-B] AX-TWIN 전문 전술 부대원 (하이브리드 모듈형 편제)
   ├─ ⚓ [2대 상시 불변 앵커]
   │    ├─ 📐 [아키텍트 / PM] 시스템·문서 아키텍처 및 공정 일정 총괄 사수

   │
   └─ 🔄 [미션별 가변 특수 슬롯 (대장장이 자유 편성)]

## 2. ⚡ [절대 헌장] 비장의 무기: 『모달 연동 제로토발 (Zero-Token, Zero-Heat)』

> **"지갑 비용(토큰) 절약보다 본부장님의 노트북 발열 0% 유지(Zero-Heat)가 최우선 목표이다."**  
> (상세 규약: `HARDWARE_RULES.md` 참조)

1. **로컬 고부하 실행 절대 금지**:
   - `torch`, `diffusers`, `whisper`, `ffmpeg` 고화질/장시간 영상 인코딩, 대형 AI 모델 추론 등을 로컬 노트북(LG 그램)에서 10초 이상 연속 실행하는 것을 영구 금지한다.
2. **모달(Modal) 클라우드 전면 위임**:
   - 대용량/고부하 작업을 담당하는 서브에이전트 코드는 반드시 `modal.App` 원격 함수 형태로 작성한다.
   - 로컬 PowerShell에서 `modal run <script.py>` 명령으로 원격 실행한다.
3. **노트북 발열 0% & 메인창 토큰 0% 동시 사수**:
   - 로컬 머신은 오직 기획, 대화, 코드 작성, 경량 파일 입출력만 담당하여 상온(발열 0%)을 유지한다.
   - 방대한 터미널 진행률 로그는 클라우드 내부에서 소멸시켜 메인 채팅창 토큰(Token-Zero)을 사수한다.
4. **결과물 자동 로컬 회수**:
   - 클라우드에서 완제된 산출물(MP4, 이미지, 데이터)은 로컬 `result/[001]~[999]` 폴더로 즉시 자동 다운로드/회수한다.

## 3. 4대 표준 폴더 (Four Core Folders) 및 자동 스캐폴딩 헌장

### 🔍 [Step 0: 사전 검문 및 자동 스캐폴딩 (Pre-flight Gateway)]
- 우리팀이 작업하는 모든 폴더(디렉토리)에 진입하는 즉시, 4대 표준 폴더 존재 여부를 자동 검사한다.
- **이미 완비된 경우**: **`[SKIP]`** (기존 파일 및 번호 100% 보존, 멱등성 사수).
- **1개라도 미비된 경우**: **`[AUTO-APPLY]`** (0.1초 만에 4대 표준 폴더 및 `conversation/CONVERSATION_TOTAL.md` 자동 생성, `result/[001]` 대기 정렬).

모든 작업 기지에는 **오직 아래 4개 폴더만 존재**하며, 그 외 임의 폴더(src, data, brain 등)의 생성은 일체 불허합니다:

1. **`conversation/`**: 본부장님과의 대화가 꼬리물기로 무한 누적되는 단일 마스터 실록 (`CONVERSATION_TOTAL.md`) 보존.
2. **`prompt/`**: 본부장님의 원천 프롬프트 및 AI 생성 프롬프트 보존.
3. **`result/`**: 모든 결과물(문서, 기획서, 데이터셋, 파이썬 소스코드, 실행기 등)이 생성순으로 `[001]`~`[999]` 번호를 달고 집결하는 유일한 산출물 기지.
4. **`upload/`**: 본부장님이 외부에서 투입하는 원천 소스 및 참고 자료 수용소.

## 4. ⚡ [초강력 절대 강제 조항] result/ [001]~[999] 무결점 순차 시리얼 규약

**대화를 통해 생성되는 모든 결과물은 다음 원칙을 단 0.001%의 예외도 없이 강제 준수해야 합니다:**

1. **단 하나의 예외 없는 [001]~[999] 번호 강제:**  
   모든 결과물은 파일명 맨 앞에 `[001]_`, `[002]_` 형식의 3자리 번호를 붙여 반드시 **`result/` 폴더에만 저장**한다.
2. **저장 위치 절대 단일화 (src 등 타 폴더 저장 일체 금지):**  
   소스코드와 데이터도 결과물 생성을 위해 사용된 순서대로 `result/`에 번호별로 저장되어야 한다.
3. **누락(결번) 절대 금지:** 1번부터 빈틈없이 1씩 순차적으로 증가한다.
4. **중첩(중복) 절대 금지:** 동일한 번호가 2개 이상의 파일에 존재하는 중첩은 일체 불허한다.
5. **모든 일련번호 1회만 적용 (Single-Use Unique Serial):** 번호 재사용 영구 차단.
6. **무번호 파일 즉각 퇴출 (Zero-Tolerance):** 번호 없는 파일의 result 폴더 진입 일체 차단.
