# [참조 02] 토큰 제로(Token-Zero) 운영 프로토콜 및 실무 노하우

## 1. 왜 토큰 제로(Token-Zero)인가?

대규모 프로젝트(예: 100페이지 기획서, 14개 씬의 영상 시나리오, 수천 줄의 코드 빌드)를 진행할 때, 대부분의 사람들은 하나의 대화창에 모든 것을 쏟아붓습니다.  
그 결과:

```
[흔한 대화창 파산 시나리오]
사용자: "이 코드 고쳐줘" (코드 500줄 출력)
사용자: "여기 에러 났어" (에러 로그 200줄 + 수정 코드 500줄 출력)
사용자: "대본도 써줘" (대본 300줄 출력)
... 누적 50,000 토큰 초과 ...
결과: AI가 처음에 정의한 캐릭터 성격과 프로젝트 목표를 잊어버리고 헛소리 시작 (Hallucination & Amnesia)
```

**토큰 제로 프로토콜**은 메인 채팅창의 토큰 소모를 **0%에 수렴**시키며, 무한히 긴 프로젝트를 첫 명령의 선명함 그대로 유지하는 혁신적인 기법입니다.

---

## 2. 토큰 제로의 4대 핵심 메커니즘

### 1) 격리된 워크스페이스 (Context Isolation)
- 메인 대화창(본부장 ↔ 총괄팀장)에는 프로젝트의 **명령과 최종 결과 요약**만 남깁니다.
- 실제 데이터 전처리, 파이썬 스크립트 실행, 대본 초안 작성 등 토큰을 대량 소모하는 작업은 **서브에이전트(`invoke_subagent`)** 또는 **로컬 백그라운드 프로세스**로 격리하여 실행합니다.

### 2) 파일 기반 핸드오프 (File-Based Handoff)
- AI끼리 대화로 수만 자의 텍스트를 주고받지 않습니다.
- 에이전트 A(리딩)가 기획서를 분석하면 `temp_blueprint.json` 또는 `blueprint.md`로 파일 저장.
- 에이전트 B(카피라이터)는 그 파일을 직접 열어서 대본을 작성하고 `result/[001]_script.md`로 저장.
- **결과:** 채팅창을 거치지 않으므로 메인 컨텍스트 토큰 소모가 0입니다.

### 3) 0-Error 자가 치유 루프 (Self-Healing Loop)
- 코드가 에러가 나면 메인 창에 "에러가 났으니 어떻게 할까요?"라고 묻지 않습니다.
- 대장장이와 프로그래머 에이전트가 터미널 실행 -> 에러 포착 -> 코드 수정 -> 재실행의 루프를 자체적으로 돌려 100% 무결점 상태가 되었을 때만 총괄팀장에게 신호를 줍니다.

### 4) 시리얼 번호 영구 보존 (`[001]` ~ `[999]`)
- 파일 이름을 덮어쓰지 않습니다.
- 매 산출물마다 `[001]_...`, `[002]_...`, `[003]_...` 형태로 시리얼 번호를 매깁니다.
- 이전 단계의 결과가 고스란히 남아 있으므로, 언제든 과거의 버전으로 롤백하거나 비교 대조할 수 있습니다.

## 3. 토큰 소비량 비교 분석

| 구분 | 일반적인 1:1 대화식 방식 | 토큰 제로 3계층 파이프라인 |
| :--- | :--- | :--- |
| **메인 창 토큰 소비** | 회차당 20,000 ~ 100,000+ 토큰 | 회차당 **500 ~ 1,500 토큰 미만** |
| **컨텍스트 오염율** | 매우 높음 (이전 지시 망각 발생) | **0% (항상 첫 프롬프트처럼 맑음)** |
| **장시간 작업 안정성** | 10~20회 대화 후 급격한 품질 저하 | 수백 번의 작업에도 일관된 품질 유지 |
| **산출물 관리** | 채팅창 텍스트 복붙 필요 (누락 위험) | 로컬 `result/`에 자동 파일 영구 보존 |
| **다중 작업 동시성** | 불가능 (한 번에 하나씩 질문) | 가능 (대장장이가 하위 부대 동시 병렬 가동) |
